# Ruby on Rails stack pack

Detect: `rails` in the Gemfile; `config/application.rb`.

## Conventions

- Follow Rails conventions: RESTful routes, thin controllers, strong parameters, models with
  validations, background jobs for slow work.
- Authorisation through the project's policy library on every action that loads a record.
- Migrations generated by Rails and reversible.

## Pitfalls

- Associations accessed in loops cause N+1 queries; use includes.
- String interpolation in where clauses is SQL injection; use bound parameters.
- Callbacks that do I/O make models slow and surprising; prefer explicit service calls.
- Jobs must be idempotent; they can run twice.

## Tests and checks

- Use the repository's own scripts first (the gate commands in the pack); add no new test runner.
- Tests through the project's runner (RSpec or Minitest via the bin scripts).

## Version notes

Version-specific APIs come from the official documentation the engine fetched for the pinned
version, in your task pack, never from memory. When the pack has no note and an API may differ
between major versions, read the installed package's types or bundled docs before using it.
